# 참고 사이트에서 착안한 메뉴 선택 개선

작성일: 2026-09-08 KST. 작성 당시 이 기능은 로컬 구현·검증 단계이며 운영 배포에 포함되지 않았다. 9월 8일 접수한 AdSense 재검토와 이 변경의 배포 상태는 별개다.

아래 구현·검증 결과와 다음 단계는 당시 기록이다. 후속 Git 이력에서는 PR #45가 [커밋 `2103d8b`](https://github.com/slayer011019/fridgemate/commit/2103d8b)로 main에 병합된 것을 확인했다(`986051a` 기준). 이번 문서 통합에서 리뷰·CI·운영 배포나 Google 최신 상태를 다시 확인하지 않았다. 당시 운영 공개 검사와 재검토 기록은 [9월 8일 후속 점검](adsense-followup-2026-09-08.md), 병합 사실과 운영 검증의 구분은 [후속 계획](public-release-plan-2026-09-08.md)을 참고한다.

## 관찰과 적용 판단

사용자가 제공한 [오늘뭐먹.com](https://xn--wh1bs8l5xa003a.com/)은 주변 식당 선택을 돕는 사이트다. 우리 서비스인 오늘뭐먹지.com은 냉장고 재료로 집에서 만들 메뉴를 탐색한다. 참고 사이트의 화면과 공개 이용 안내를 읽고, 목적에 맞는 상호작용만 적용했다.

| 참고한 흐름 | 확인한 근거 | FridgeMate에 적용할 방향 |
| --- | --- | --- |
| 조건을 정하고 마지막 선택을 돕는다 | 홈의 반경·식사 유형·음식 종류 선택과 ‘오늘의 점심 돌리기’ 버튼 | 기존 재료 탐색에 ‘메뉴 하나 골라보기’를 추가한다. 선택한 재료와 가장 많이 겹치는 후보에서 고른다. |
| 결과에서 바로 다음 행동으로 이동한다 | [이용 안내](https://xn--wh1bs8l5xa003a.com/how-to-use)가 결과 카드와 지도 연결·다시 돌리기를 설명한다 | 선택한 메뉴에서 정확한 내부 조리법과 준비 목록으로 연결하고, 다음 선택에서는 직전 결과를 제외한다. |
| 이용자가 처한 상황으로 사용법을 설명한다 | 홈에서 선택 고민·후보 중 결정·비 오는 날 등의 가이드를 연결한다 | 기존 ‘예시 냉장고로 메뉴 고르기’, ‘먼저 쓸 재료로 메뉴 고르기’ 동선을 유지한다. 새 글을 늘리기 전에 실제 준비·조리 예시를 보강하는 방향으로 활용한다. |

홈 UI는 직접 확인했으나 룰렛 실행 후 결과 카드까지 정상 작동하는지는 확인하지 못했다. 결과 카드 설명은 이용 안내에서 확인한 내용이다. 지도 영역에는 ‘서비스 오픈 예정’ 표시가 있어 식당·위치 데이터 정확성이나 지도 완성도를 검증한 것으로 보지 않는다. 화면에 광고가 표시되는 사실만으로 해당 사이트의 AdSense 승인 상태나 우리 사이트 승인 가능성을 판단할 수 없다.

참고 사이트의 식당 데이터·문구·코드를 가져오지 않았다. 기존 공개 레시피, 출처, 자체 편집 설명을 이용했다.

## 이번 구현

- 홈과 `/recipes`의 기존 공개 탐색에 선택 보조 영역을 추가했다.
- 재료 조건이 없으면 전체 공개 카탈로그 100개, 조건이 있으면 일치 재료 수가 가장 높은 후보에서 하나를 고른다. 현재 화면에 표시된 6개 또는 12개 카드에만 한정하지 않는다.
- 무작위 선택은 버튼을 누를 때만 발생한다. 초기 렌더링·프리렌더링에서 결과를 정하지 않는다.
- 다시 고르면 직전 메뉴를 제외한다. 후보 하나를 고른 뒤에는 선택 버튼을 비활성화하고 조리법 링크를 제공한다. 후보가 없으면 영역을 표시하지 않는다.
- 재료 조건 또는 브라우저 이력이 바뀌면 결과를 초기화한다. 상세 링크에는 탐색용 `have` 조건을 그대로 전달한다.
- 결과를 자동 저장하거나 이동하지 않는다. 냉장고·팬트리 보유 여부와 오늘 메뉴 기록도 변경하지 않는다. 실제 종류·분량과 추가 준비 재료는 상세에서 확인한다.
- 결과 텍스트는 `aria-live`로 알린다. 다중 후보에서 다시 고르기 버튼을 유지해 키보드 포커스를 보존한다.

예를 들어 `오이,사과`의 최고 일치 후보는 32번 순두부 사과 소스 오이무침과 511번 닭고기또띠아 두 개다. `순두부`를 추가하면 최고 일치 후보는 32번 하나다. 이 선택 기준은 재료 관련성에 따른 탐색 보조이며, 필요한 모든 재료를 보유했거나 바로 조리할 수 있다는 판정은 아니다.

이 기능으로 공개 상세 수나 색인 대상 URL을 늘리지 않았다. 콘텐츠 개선의 다음 우선순위는 아직 준비 목록을 검토하지 않은 상세의 실제 활용 설명·준비 확인을 보강하는 것이다. 기능 추가만으로 AdSense의 ‘가치가 별로 없는 콘텐츠’ 사유가 해소됐다고 단정하지 않는다.

## 검증

검증 대상은 이 작업 폴더의 로컬 소스다. 운영 계정 로그인, 서버 동기화, AdSense 설정 변경은 이번 검증 범위에 포함되지 않는다.

- 컴포넌트 9개 사례: 명시적 클릭, 전체 후보 풀, 최고 일치 수, 직전 결과 제외, 키보드·저장소 보존, 후보 없음·한 개, URL 변경·브라우저 이력 초기화.
- 공개 E2E: 데스크톱 1280×900과 모바일 크기 390×844에서 기존 탐색·준비 흐름과 새 선택→정확한 상세 연결을 확인한다. 무작위 값을 고정해 실제 카탈로그의 특정 상세를 검증하며, 후보 전체·다시 고르기는 컴포넌트 검사와 별도 브라우저 QA에서 확인한다. 외부 식약처 이미지 응답은 E2E에서 대체한다.
- 독립 Chromium QA: 두 화면 크기에서 총 14개 항목 통과. 실제 두 후보의 번갈아 선택, 단일 후보, 조건 변경, 준비 체크, 빈 결과, Enter·Tab, 가로 넘침을 확인했다. 신규 앱 오류와 허용되지 않은 요청은 0개였다.
- 독립 QA 기록: [JSON](validation/public-quick-pick-2026-09-08/independent-report.json), [모바일 결과](validation/public-quick-pick-2026-09-08/mobile-selected.png), [데스크톱 결과](validation/public-quick-pick-2026-09-08/desktop-selected.png). JSON과 두 캡처는 PR 검토용으로 보존했으며 웹사이트 배포 자산이 아니다. 기존 로컬 QA 기록으로, 이번 PR의 새 실행 결과와 구분한다.
- 전체 테스트에서 기존 메뉴 결정 서비스의 8월 30일 fixture가 실제 날짜의 지원 동기화 기간을 벗어나는 실패를 발견했다. 테스트 시간을 fixture 날짜로 고정하고 종료 후 복원했다. 프로덕션 날짜 제한은 바꾸지 않았다.
