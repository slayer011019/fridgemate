# 오늘뭐먹지 AdSense 공개 사이트 점검

점검일: 2026-09-06 (KST)

대상: https://xn--wh1bs8l5xa003adme.com/

> 후속 조사: 공개 기능은 최신 운영 커밋 `ca7b6d2`에 포함된 PR #41에서 삭제된 것으로 확인했다. 최초 점검의 로컬 체크아웃이 16개 커밋 뒤처져 있었다. [배포 원인 기록](deployment-recovery-notes.md)과 [개선 진행 상태](adsense-improvement-plan.md)를 함께 참고한다. 아래 표와 화면 평가는 개선 배포 전의 관찰 기록이며, 이번 구현이 운영에 반영됐다는 뜻이 아니다.

## 핵심 결론

**로컬에서 준비한 공개 콘텐츠 108개 URL이 운영 도메인에서 모두 HTTP 404를 반환한다.** 운영 사이트맵에는 홈, 메뉴 추천, 서비스 소개, 문의, 개인정보 처리 안내 5개만 있다. 현재 로컬 소스와 기존 `dist`에는 공개 레시피 100개, 재료 허브 6개, 가이드 2개를 포함한 113개 공개 URL이 있다.

현재 사용자에게 제공되는 페이지는 빈 냉장고 대시보드와 외부 검색 링크를 가진 메뉴 추천이 중심이다. 이는 AdSense의 ‘가치가 별로 없는 콘텐츠’ 판단과 연결될 가능성이 높은 관찰이다. 다만 Google의 내부 심사 기록과 심사 당시 배포 상태는 확인할 수 없으므로, 개별 거절 원인으로 확정하지 않는다.

## 확인 범위와 결과

| 점검 | 결과 |
| --- | --- |
| 운영 사이트맵의 5개 공개 URL | 전부 HTTP 200 |
| 로컬 사이트맵의 추가 공개 URL 108개 | 전부 운영 HTTP 404 |
| 기존 로컬 `dist` 공개 URL 113개 | 파일, canonical, 프리렌더 표시, index 메타, 사이트맵 등재 누락 0개 |
| 홈·메뉴 추천·소개·문의 | 비로그인 브라우저 화면 확인 |
| 냉장고·재료 추가·사진 등록·로그인 | 비로그인 화면 진입 확인; 입력·저장·로그인·이미지 전송은 수행하지 않음 |
| 개인정보 처리 안내 | 운영 응답 HTML 및 메타 확인 |
| HTTP / www 주소 | 대표 HTTPS 도메인으로 연결 후 200 |
| robots.txt / sitemap.xml / ads.txt | 모두 200 |
| 존재하지 않는 임의 경로 | HTTP 404 |
| Mediapartners-Google User-Agent의 `/recipes` 요청 | 200, 일반 요청과 동일하게 공개 레시피 상세 링크 없음 |

User-Agent 비교는 실제 Google 크롤러 IP에서의 접근이나 Google의 렌더링 성공을 검증한 것이 아니다. URL 검사와 실제 색인 상태는 Search Console에서 별도로 확인해야 한다.

## 우선순위별 발견 사항

### 1. 공개 콘텐츠가 운영 도메인에서 제공되지 않음 — 최우선

- 운영 `/sitemap.xml`: 5개 URL.
- 로컬 `dist/sitemap.xml`: 113개 URL.
- 레시피 100개, 허브 6개, 가이드 2개에 대한 운영 응답 상태 전수 확인: 108개 모두 404.
- 예: `/recipes/ingredients/tofu`, `/guides/fridge-cleanout`, `/guides/use-expiring-ingredients`, `/recipes/28-새우-두부-계란찜`.
- 운영 홈·메뉴 추천·푸터에서도 공개 레시피 상세 및 가이드 내부 링크가 발견되지 않았다.
- 운영 메인 JS는 `index-CtJPKFF5.js`, 기존 로컬 `dist`는 `index-B9u6lClj.js`다.

단순히 ‘오래된 버전’이라고 확정할 수는 없다. 운영에는 일부 후속 보안 설정과 문구도 존재한다. 어떤 체크아웃·브랜치·빌드 경로·산출물을 운영 도메인에 연결했는지 확인해야 한다.

최초 조사에서는 인증된 Vercel CLI 범위에 해당 도메인이 없고 로컬 `.vercel` 연결도 없어 배포 원인을 확인하지 못했다. 후속 GitHub 조사로 팀/프로젝트 `fridgemates-projects/fridgemate`, Production 배포 기록 `6237293328`, 커밋 `ca7b6d2`, 공개 기능 삭제 diff를 확인했다. 도메인의 현재 alias 대상과 Vercel 빌드 로그는 관리자 접근 후 직접 대조해야 한다. 자세한 근거는 위 배포 원인 기록에 있다.

관련 코드: `src/utils/routeMetadata.js`, `scripts/generate-seo-pages.js`, `scripts/verify-seo-output.js`, `vercel.json`, `package.json`.

### 2. 첫 방문의 공개 효용과 최초 HTML이 약함 — 높음

- 홈의 핵심 영역은 재료가 없다는 안내와 추천 가능한 레시피가 없다는 안내다.
- 운영 `/recipes` 최초 HTML에는 조미료 설정, 로딩 안내, 추천 영역 제목은 있지만 실제 레시피 이름·조리법·내부 상세 링크가 없다.
- JavaScript 실행 후 브라우저에는 64개 메뉴 카드가 표시된다. 따라서 사이트 전체가 빈 HTML이거나 JavaScript 자체가 실행 불가하다는 의미는 아니다.
- 메뉴 카드에는 짧은 활용 설명과 만개의레시피·유튜브·네이버 검색 링크가 있고, 사이트 내부에서 완성된 조리법을 읽는 경로는 확인되지 않았다.
- 서버 카탈로그 추천은 로그인 안내로 제한된다. 냉장고 관리·재료 추가·사진 등록 화면 자체는 비로그인 상태에서도 열린다.

권장: 입력 전에도 읽고 활용할 수 있는 대표 레시피와 실제 냉장고 활용 사례를 홈에 제공하고, 공개 상세 본문과 내부 링크가 최초 HTML에도 존재하도록 한다. 사용자별 냉장고 데이터를 공개하거나 검색에 노출할 필요는 없다.

### 3. 재료가 없는데 ‘핵심 재료는 대부분 맞음’으로 설명 — 높음

운영 브라우저와 로컬 추천 함수에서 모두 확인했다. 재료 0개·팬트리 보유 0개일 때 64개 메뉴의 점수는 0인데, 일부 카드에 핵심 재료가 대부분 맞다는 설명이 나온다. 버섯볶음은 `0%`, `0/0개 일치`, 버섯류 조건 부족과 긍정적 설명이 함께 표시된다.

관련 코드: `src/utils/recommendations.js:291`, `src/utils/recommendations.js:427`, `src/pages/RecipesPage.jsx:257`.

권장: 보유 데이터가 없을 때는 탐색용 메뉴로 명확히 안내하고, 실제 보유 여부와 필수 재료 그룹 충족 여부를 확인한 뒤 매칭 설명을 생성한다.

### 4. 준비된 100개 레시피도 고유 가치 보완 필요 — 배포 후 점검

이 항목은 **운영에서 열리지 않는 로컬 콘텐츠에 대한 평가**다. 현재 운영 심사에서 100개 레시피가 검토됐다고 가정하지 않는다.

- 100개 모두 식품안전나라 원문 기반 재료·이미지·조리 단계·영양·저감 조리 팁·출처를 표시한다.
- 원문을 정확히 표시하고 출처를 밝히는 장점은 있으나, 별도 직접 조리 결과·대체재 판단·실패 방지 설명·실제 냉장고 활용 사례는 없다.
- 가이드 2개는 인트로와 5개 소제목·본문을 합쳐 각각 약 417자이며 일반적인 사용 안내가 중심이다. 이 수치는 공식 최소 글자 수 기준이 아니다.
- 재료 허브 6개는 키워드 기반 분류와 링크 모음 중심이며, 선별 이유나 메뉴 간 비교가 부족하다.

권장: 페이지 수 증가보다 방문자가 실제로 얻는 추가 효용을 강화한다. 예를 들어 같은 남은 재료로 가능한 메뉴 비교, 필요한 분량, 대체 가능 여부의 근거, 실제 조리에서 확인한 주의점 등을 제공한다. 직접 해보지 않은 조리 경험이나 사진을 만들어 사실처럼 표시하지 않는다.

관련 코드: `scripts/export-public-recipes.js`, `src/pages/PublicRecipePage.jsx`, `src/features/recipes/recipeContentHubs.js`, `src/pages/IngredientHubPage.jsx`.

## 정상 확인한 항목

- 공개 5개 페이지에 경로별 제목·description·canonical·index 메타와 구조화 데이터가 있다.
- 공개 페이지를 robots.txt에서 일괄 차단하지 않는다. `Google-Extended` 차단은 Googlebot 전체 차단으로 해석할 수 없다.
- 로그인·재료·가져오기 화면의 최초 HTML과 HTTP 헤더에는 noindex가 있다.
- 공개 `ads.txt` 게시자 ID와 HTML의 `google-adsense-account` 값이 일치한다.
- 서비스 소개·문의 이메일·개인정보 처리 안내가 존재한다. 문의 이메일은 브라우저에서 mailto 링크로 표시된다.
- HTTPS와 www 통합이 동작하며, 확인한 홈 브라우저 콘솔에 오류·경고 기록은 없었다.

따라서 소개 페이지 부재, ads.txt 누락, 도메인 연결 실패를 이번 거절의 주원인이라고 설명할 근거는 없다.

## 광고 활성화 전 별도 확인

운영 CSP는 AdSense 스크립트 출처를 허용하지 않고 `frame-src 'none'`을 사용한다. 나중에 광고 게재를 활성화하면 필요한 출처를 정확히 허용해야 한다. 현재 ‘가치가 낮은 콘텐츠’ 거절의 확정 원인이라는 의미는 아니다.

로컬 홈의 광고 컴포넌트는 슬롯 설정이 유효하면 빈 냉장고 화면에서도 표시될 수 있다. 광고 활성화 전에 실질 콘텐츠가 없는 상태의 광고 위치를 점검해야 한다. 이번 브라우저 점검에서는 실제 광고 노출을 확인하지 않았다.

## 다음 작업과 검증 기준

1. 실제 운영 Vercel 프로젝트·배포 ID·커밋·빌드 명령·출력 폴더·도메인 연결을 확인한다. 기존 수정 파일을 보존하고 올바른 소스와 배포 대상을 맞춘다.
2. 공개 콘텐츠가 포함된 배포 후 113개 공개 URL의 상태·본문·메타·내부 링크를 운영 도메인에서 다시 확인한다. 사이트맵 파일만 늘리는 것으로 완료 처리하지 않는다.
3. 재료 0개 추천 설명과 홈의 첫 방문 경험을 수정한다. 콘텐츠 품질은 실제 사용 사례를 기준으로 보완한다.
4. Search Console에서 대표 홈·레시피 상세·가이드의 실시간 URL 검사와 렌더링을 확인하고, 필요하면 갱신된 사이트맵을 제출한다.
5. 변경이 운영에 반영되고 접근·콘텐츠를 확인한 뒤 AdSense 재검토를 요청한다. 특정 페이지 수나 글자 수로 승인을 보장할 수 없다.

## 한계와 변경 내역

- Google 내부 심사 기록·심사 시점의 사이트·Search Console 색인/직접 조치 상태는 미확인이다.
- 로그인 후 CRUD·동기화·OCR 실행·모바일별 레이아웃·성능 측정·보안 침투 검사는 이번 공개 콘텐츠 감사 범위에 포함하지 않았다.
- 점검은 HTTP/HTML 확인, 비로그인 브라우저 탐색, 기존 빌드 산출물 검증, 로컬 추천 함수 재현으로 진행했다. 앱 코드 변경이 없어 전체 단위 테스트와 새 빌드는 실행하지 않았다.
- 생성 파일은 이 점검 보고서뿐이다. 앱 코드·배포·심사 신청을 변경하지 않았다.
